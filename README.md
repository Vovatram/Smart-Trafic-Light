# SmartTrafficLight

3D-визуализация пешеходного перехода через дорогу.

- **БД** — PostgreSQL 18 (параметры перехода: число полос, ширина, состояние светофоров)
- **Бэкенд** — FastAPI + SQLAlchemy 2.0 (async, psycopg3) + Alembic
- **Фронтенд** — React 19 + Vite + Tailwind 4 (`@tailwindcss/vite`) + react-three-fiber

Дорога — прямой участок с пешеходным переходом посередине. У каждого направления полосы лежат со своей правой стороны по ходу движения — правостороннее движение. N и K независимо меняются в панели справа («Настройка перехода»), разметка и столбы со светофорами (автомобильный + пешеходный на каждом) пересчитываются сразу. Числовые настройки везде (N/K, длина дороги, ширина полосы/перехода, длительности фаз, интенсивность, параметры ИТС-объектов) не имеют верхней границы — единственное ограничение "не в минус" (для геометрии — строго больше нуля, чтобы не вырождалась); исключение — поворот столба (`rotation_deg`), у него честный диапазон [0°, 360°), потому что это угол, а не длина. У степперов +/- можно зажать для быстрой прокрутки — короткий клик, как раньше, делает один шаг, через ~0.4 с зажатия начинается автоповтор.

Панель справа — стопка сворачиваемых карточек (клик по заголовку открывает/закрывает): «Настройка перехода», «Трамвай, автобус, вело», «Вид сцены», «ИТС-объекты», «Режим светофора», «Генерация».

## 🚌 Трамвай, автобус, велополоса

Отдельная карточка, две колонки — «Вперёд (N)» и «Назад (K)»:

- **Трамвайные пути** — чекбокс ЗАМЕНЯЕТ самую левую (ближе к оси, откуда едет встречный поток) полосу этого направления на трамвайную: общее число полос (N/K) не меняется, но обычные машины в неё больше не спавнятся — только трамвай.
- **Автобусная полоса** — то же самое для самой правой (ближе к обочине) полосы.
- **Велополоса** — наоборот, добавляет ширину: узкая полоса между проезжей частью и тротуаром, свой цвет покрытия и дашевая разметка. Пешеходный переход (зебра) при этом растягивается и на неё — велополоса не в тупик.
- Если включена трамвайная/автобусная полоса, рядом появляется выбор остановки: без остановки / до перехода / после перехода. Остановка — только жёлтая ломаная линия на полотне дороги (как в жизни размечают зону остановки), посадка/высадка и задержка движения на ней не имитируются.
- Чекбоксы недоступны, если у направления вообще нет полос (N или K = 0). При включении обеих полос-разъединителей на направлении с 1 полосой обе претендуют на неё же — это не проверяется отдельно, визуально трамвайная разметка и автобусный тон совпадут.
- Границу с обычной полосой рисуют сплошной (не прерывистой), как в жизни на выделенных полосах — это только разметка. Реально не заезжают на неё машины/спецтехника потому, что для них эта полоса просто не в списке доступных (`carLaneIndices` в `layout.ts`) — если полосу сделали трамвайной/автобусной посреди симуляции, машины, что уже были в ней, снимаются с трассы в тот же кадр, а не продолжают ехать через остановку.

## 📷 ИТС-объекты

Сверху — выбор типа (камера, микроволновый датчик, индукционная петля, I2V) и кнопка «Добавить» — переключает сцену на вид сверху и режим установки, кликом по сцене ставите объект. Каждый объект в списке можно выключить отдельным чекбоксом слева от его кнопки (или в самом редакторе) — выключенный ничего не детектирует и виден на сцене приглушённым серым, но не удаляется и не пропадает из списка. Камера и датчик встают на столб у обочины (угол обзора, угол поворота, радиус обзора, высота столба; у камеры ещё и ссылка на трансляцию), петля ложится прямо на полотно дороги (позиция + длина).

**I2V/V2I** — придорожный блок связи "инфраструктура-транспорт": в отличие от камеры/датчика он не направленный (угол обзора всегда 360° — виден полный круг, не сектор, поле «Угол обзора» / «Поворот» в редакторе для него скрыты за ненужностью) и детектирует ТОЛЬКО общественный транспорт (трамвай, автобус) и спецтехнику — обычные машины и пешеходов I2V не видит вообще, как бы близко они ни были. Радиус действия по умолчанию 300 м (поле «Радиус действия», тот же `view_radius`, что у камеры/датчика, просто без угла) — в этом радиусе трамвай/автобус/спецтехника виден независимо от того, попадает ли он в сектор обзора какой-то камеры. Пойманный именно через I2V (а не через камеру/датчик) транспорт получает продольную красную линию (вдоль всей длины кузова, а не поперечную полосу, как у обычной раскраски по детектирующим сенсорам) — это единственное, что рисует I2V "от себя"; сама линия не заменяет обычную раскраску по камерам/датчикам, а показывается рядом с ней (если камера/датчик его тоже видят — полосы поперёк остаются как обычно; если видит только I2V — кузов серый одним тоном, плюс линия).

Ниже — список уже поставленных объектов, клик по любому (в списке или прямо на сцене) добавляет/убирает его из выбора и открывает слева панель редактирования. Панель показывается, только если выбран ровно один объект. Клик по пустому месту сцены сбрасывает выбор. У каждого объекта свой цвет из общей палитры.

## ⚙️ Генерация и симуляция

«Генерация» — сама генерация идёт постоянно всегда; раскрытие этой панели (клик по заголовку) только показывает/прячет 2D-плашки настройки интенсивности над каждым из «начал» потока. 
- Каждое "начало" — это ряд плашек рядом друг с другом. Для концов дороги — машины, спецтехника и (если включены) трамвай/автобус — стоят на фиксированном расстоянии 100 м от перехода (`GENERATION_BADGE_DISTANCE` в `GenerationBadges.tsx`).
- У каждой плашки есть кнопка «Спавн» для немедленного создания агента нужного типа.
- В режиме генерации на сцене остаются только плашки интенсивности — обратный отсчет светофора скрыт, чтобы не загромождать вид сверху.
- Машины и пешеходы процедурно спавнятся по заданной интенсивности, едут/идут только на зелёный/«идите» и отрисовываются только пока их видит зона обзора хотя бы одной камеры или микроволнового датчика — цветом того объекта, который их видит (если видят несколько — кузов расписан полосками ПОПЕРЁК, до 6 штук одновременно).
- Интенсивность не ограничена сверху ни на бэкенде, ни на фронтенде (только `>= 0`).

## 🚦 Режимы управления светофором

Светофор управляется одним из 4 режимов (панель «Режим светофора»):

- **Ручной** — клик по автомобильной или пешеходной лампе на сцене раскрывает эту панель и показывает кнопки выбора цвета прямо в ней.
- **Адаптивное управление** — заглушка: всегда зелёный пешеходам, красный машинам.
- **Циклы** — «зелёный машинам → жёлтый → красный всем → зелёный пешеходам → красный всем» по кругу. Можно завести сколько угодно именованных циклов.
- **Кнопка** — по умолчанию горит зелёный машинам; кнопка вызова (в панели или автоматически при упоре пешехода в границу перехода) переключает на пешеходов через жёлтый и красный, но не раньше настраиваемого минимального зелёного машинам.

Жёлтая фаза (3 с) — общая для циклов и кнопки. Обе «красный всем» настраиваются раздельно (`all_red_after_cars_s` и `all_red_after_peds_s`).

Светофоры — плоские, современные. Над каждым светофором отображается числовой бейдж с обратным отсчетом времени до смены сигнала, а также живыми счётчиками пешеходов и машин по направлениям (определяется проекцией позиций столбов через текущую камеру `Vector3.project`).

## 📈 Журнал, графики и Replay сцены

Панель «История» открывает нижнюю выдвижную панель с двумя вкладками:
- **Журнал** — построчно фиксирует время, режим, активный сигнал и описание при каждой смене (`useSignalState`). Поддерживает фильтрацию по конкретным ИТС-объектам (`device_id`) или уровню перехода (`device_id IS NULL`).
- **Графики** — визуализация интенсивности машин и пешеходов по направлениям на основе снимков (`traffic_metric_snapshots`), сохраняемых каждые 30 с.

**Таймлайн (Replay):**
Внизу расположена общая лента времени с ползунком, `play/pause`, множителем скорости ($\times 1, \times 4, \times 16, \times 60$) и кнопкой «Сейчас». Перемещение ползунка подменяет 3D-сцену покадровым replay на основе снимков позиций (`scene_snapshots`, каждые 2 с с линейной интерполяцией). Живая симуляция при этом продолжает работать в фоне. Глубина хранения истории настраивается параметром `log_retention_hours`.

## 📁 Структура проекта

```text
backend/
  app/
    api/crossings.py    REST-роуты перехода, журнала, метрик и снимков сцены
    models.py           crossings, its_devices, signal_cycles, signal_log_entries, etc.
    schemas.py          Pydantic-схемы
    seed.py             Демо-переход
  alembic/              Миграции БД
  run.py                Точка входа для Windows (настройка EventLoop)
frontend/
  src/
    scene/              3D-сцена (дорога, разметка, рельсы, полосы, светофоры, ИТС)
    hooks/              Хуки логики фаз (`useSignalState`) и таймлайна (`useHistoryPlayback`)
    components/         Интерфейсные карточки и панели управления
```

## 🚀 Запуск проекта

### 1. База данных
```sql
CREATE ROLE backend LOGIN PASSWORD '...';
CREATE DATABASE "SmartTraficLight" OWNER backend;
```

### 2. Бэкенд
```bash
cd backend
py -3.14 -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
cp .env.example .env         # Укажите пароль пользователя БД
.venv/Scripts/alembic upgrade head
.venv/Scripts/python -m app.seed
.venv/Scripts/python run.py
```
> **Windows:** Запускайте именно `python run.py` (из-за особенностей async-режима `psycopg` и `ProactorEventLoop`), а не `-m uvicorn`.

### 3. Фронтенд
```bash
cd frontend
npm install
npm run dev
```
Интерфейс доступен по адресу: `http://localhost:5173`

## 📐 Система координат

Дорога идёт вдоль оси **Z**, ось **X** — поперёк, **Y** — вверх. Правостороннее движение: для транспорта в направлении $+Z$ правая сторона находится при $X < 0$, в направлении $-Z$ — при $X > 0$. Столбы светофоров и ИТС-объекты позиционируются на основе текущей геометрии полос.
