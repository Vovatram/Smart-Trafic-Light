# SmartTrafficLight

3D-визуализация пешеходного перехода через дорогу.

- **БД** — PostgreSQL 18 (параметры перехода: число полос, ширина, состояние светофоров)
- **Бэкенд** — FastAPI + SQLAlchemy 2.0 (async, psycopg3) + Alembic
- **Фронтенд** — React 19 + Vite + Tailwind 4 (`@tailwindcss/vite`) + react-three-fiber

Дорога — прямой участок с пешеходным переходом посередине. У каждого
направления полосы лежат со своей правой стороны по ходу движения —
правостороннее движение. N и K независимо меняются от 0 до 5 в панели
справа («Настройка перехода»), разметка и столбы со светофорами
(автомобильный + пешеходный на каждом) пересчитываются сразу.

Панель справа — стопка сворачиваемых карточек (клик по заголовку
открывает/закрывает): «Настройка перехода», «Вид сцены», «ИТС-объекты»,
«Режим светофора», «Генерация».

«ИТС-объекты»: сверху — выбор типа (камера, микроволновый датчик,
индукционная петля) и кнопка «Добавить» — переключает сцену на вид сверху
и режим установки, кликом по сцене ставите объект. Камера и датчик встают
на столб у обочины (угол обзора, угол поворота, радиус обзора, высота
столба; у камеры ещё и ссылка на трансляцию), петля ложится прямо на
полотно дороги (позиция + длина). Ниже — список уже поставленных
объектов, клик по любому (или по объекту прямо на сцене) открывает слева
панель редактирования с кнопкой удаления. Ctrl/Cmd+клик по объекту (в
списке или на сцене) добавляет его к выбору вместо замены — если выбрано
больше одного, панель редактирования не показывается (нечего редактировать
одной формой), но сектор обзора виден у каждого из выбранных сразу, для
сравнения покрытия. Клик по пустому месту сцены сбрасывает выбор. У
каждого объекта свой цвет из общей палитры.

«Генерация» — переключатель «Реальный режим» / «Генерация»: во втором
случае над каждым из 4 «начал» потока (оба конца дороги, обе обочины
перехода) появляются 2D-плашки с числом машин/пешеходов в час. Сама
генерация идёт постоянно в обоих режимах — переключатель только
показывает/прячет плашки настройки: машины и пешеходы процедурно
спавнятся по заданной интенсивности, едут/идут только на зелёный/«идите»
(останавливаются перед стоп-линией/границей перехода — не мгновенно, а
честно доезжая до неё; кто уже въехал/вышел на переход, доезжает/доходит
несмотря на смену сигнала) и отрисовываются только пока их видит зона
обзора хотя бы одной камеры или микроволнового датчика — цветом того
объекта, который их видит (двумя цветами, если видят два).

Светофор управляется одним из 4 режимов (панель «Режим светофора»):

- **Ручной** — клик по автомобильной или пешеходной лампе на сцене
  раскрывает эту панель и показывает кнопки выбора цвета прямо в ней.
- **Адаптивное управление** — заглушка: всегда зелёный пешеходам, красный
  машинам (настоящей адаптивной логики под капотом нет).
- **Циклы** — «зелёный машинам → жёлтый → красный всем → зелёный пешеходам
  → красный всем» по кругу (две отдельных красных фазы: после машин через
  жёлтый, и после пешеходов). Можно завести сколько угодно именованных
  циклов (длительности задаются по отдельности) и переключаться между ними,
  активный запоминается у перехода.
- **Кнопка** — по умолчанию горит зелёный машинам; кнопка вызова (в панели,
  либо автоматически — как только подошедший пешеход упирается в границу
  перехода на «стоп», это эквивалентно нажатию) переключает на пешеходов
  через жёлтый и красный, но не раньше настраиваемого минимального
  зелёного машинам — причём засчитывается и то время, что машины уже ехали
  до вызова: если зелёный горел 70 с при минимуме 30, переключение
  начинается на ближайшем тике, а не откладывается ещё на 30 с.

Жёлтая фаза (3 с, не настраивается) — общая для циклов и кнопки. А вот обе
«красный всем» настраиваются раздельно (`all_red_after_cars_s` и
`all_red_after_peds_s`, своя панелька-степпер на каждую) — например, можно
дать пешеходам больше времени после жёлтого, чем машинам после перехода.
Над каждым светофорным столбом — два независимых
числовых бейджа, автомобильный и пешеходный (у них разное расписание смены
цвета): обратный отсчёт до следующей смены этого конкретного сигнала, либо
«АУ», когда для него нет активного расписания (адаптивный режим, или режим
«Кнопка» в ожидании вызова). В ручном режиме оба бейджа скрыты. Вся эта
логика фаз считается на клиенте (`useSignalState`), не на сервере — БД
хранит только конфигурацию (режим, циклы, длительности), а не «в какой фазе
сейчас находимся».

## Структура

```
backend/
  app/
    api/crossings.py   REST-роуты перехода
    models.py           таблица crossings
    schemas.py           Pydantic-схемы
    seed.py               демо-переход
  alembic/                миграции
  run.py                   точка входа для Windows (см. ниже, почему не `-m uvicorn`)
frontend/
  src/
    scene/                3D-сцена: дорога, светофоры, ИТС-объекты,
                            TrafficSimulation.tsx — генерация и движение
                            машин/пешеходов, GenerationBadges.tsx — плашки
                            интенсивности, SignalStatusBadge.tsx — обратный
                            отсчёт фазы, detection.ts — кто кого видит
    hooks/useSignalState.ts  фазы светофора: ручной/адаптив/циклы/кнопка,
                              полностью на клиенте, тикает раз в 200мс
    components/            сворачиваемые панели интерфейса (ui.tsx Card):
                            InfoPanel, SignalModePanel, DeviceEditor
```

## Запуск

### 1. База данных

```sql
CREATE ROLE backend LOGIN PASSWORD '...';
CREATE DATABASE "SmartTraficLight" OWNER backend;
```

### 2. Бэкенд

```bash
cd backend
py -3.14 -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
cp .env.example .env          # вписать пароль пользователя backend
.venv/Scripts/alembic upgrade head
.venv/Scripts/python -m app.seed
.venv/Scripts/python run.py
```

API: http://localhost:8000/api/health, документация: http://localhost:8000/docs

> **Windows:** запускать именно `python run.py`, а не `python -m uvicorn app.main:app`.
> `psycopg` в async-режиме несовместим с `ProactorEventLoop`, который Windows
> выбирает по умолчанию — `run.py` переключает политику на
> `WindowsSelectorEventLoopPolicy` до того, как uvicorn создаст свой event
> loop; через `-m uvicorn` app-модуль импортируется уже после этого момента,
> и переключать поздно.

### 3. Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Интерфейс: http://localhost:5173 (запросы `/api` проксируются на бэкенд).

## Система координат

Дорога идёт вдоль оси **Z**, ось **X** — поперёк, **Y** — вверх (правая тройка,
как в three.js); переход — зона вокруг Z = 0. Правостороннее движение: для
машины, едущей в сторону +Z, «право» — это -X (правило правой руки:
`right = (-Fz, 0, Fx)` для вектора движения F); для машины, едущей в сторону
-Z, «право» — это +X. Поэтому полосы направления N (едут в сторону +Z) лежат
при X < 0, полосы направления K (едут в сторону -Z) — при X > 0. Столбы
светофоров стоят снаружи проезжей части, их X пересчитывается из текущего
числа полос — см. `frontend/src/scene/layout.ts`. ИТС-объекты, в отличие от
светофоров, хранят абсолютные (x, z) — туда, куда кликнул пользователь в
режиме установки, — и не пересчитываются при изменении числа полос.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/crossings` | список переходов |
| `POST` | `/api/crossings` | создать переход |
| `GET` | `/api/crossings/{id}` | переход целиком |
| `PATCH` | `/api/crossings/{id}` | изменить число полос, ширину, светофоры, режим, интенсивность |
| `DELETE` | `/api/crossings/{id}` | удалить переход |
| `POST` | `/api/crossings/{id}/its-devices` | добавить ИТС-объект (камера/датчик/петля) |
| `PATCH` | `/api/its-devices/{id}` | изменить параметры объекта |
| `DELETE` | `/api/its-devices/{id}` | удалить объект |
| `POST` | `/api/crossings/{id}/signal-cycles` | добавить цикл светофора |
| `PATCH` | `/api/signal-cycles/{id}` | изменить длительности цикла |
| `DELETE` | `/api/signal-cycles/{id}` | удалить цикл |
